# 点点 v3.0：商业化信任修复（设计说明）

日期：2026-11-12 · 基线：v2.2 · 范围：仅前端原型（后端 / 灰度 / 回滚不在原型中演示）

## 核心逻辑
来源标签只负责「告知来源」；验证详情放进用户自己展开的面板里；AI 不替用户下结论。

## 改动
1. **删除筛选与隐藏**：去掉「只看真实用户体验」芯片及其提示、偏好设置里的「是否接受品牌合作内容」、隐藏逻辑、隐藏提示和筛选后的空状态。任何位置都不出现「过滤品牌内容」的开关。
2. **来源角标**：笔记字段 `collab_status: 'marked' | 'unmarked'`。没有合作数据的笔记统一按 `unmarked` 处理。
   - 推荐卡片右上角放一个浅灰色角标：引用的笔记里只要有一篇是 marked，就显示「已标注合作」，否则显示「未标注合作」。
   - 卡片内「引用的笔记」每一行、完整依据弹窗里的笔记行、笔记详情页，都带同样的浅灰色角标。
   - 已标注和未标注用同一种视觉样式，没有颜色上的区别。
   - 点击角标打开对应原文。原文页显示「来自点点回答」，返回后对话位置保持不变。
3. **可信度验证面板**：卡片下方放可折叠的入口「这条推荐为什么可信？」。
   - 展开时调用 mock 接口 `/api/ai/recommendation/verify`，先显示约 400ms 骨架屏。
   - 面板展示 4 个维度：🛒 购买验证、💬 互动真实性、📝 文本相似度、👥 用户多样性。每个维度都有数值、条形图、说明文案和数据来源。
   - 底部入口「这 X 位是谁 ›」从底部滑出用户列表，每位用户显示已验证购买、粉丝数、历史内容覆盖品类。点击用户进入用户主页层。
   - 样本不足时显示「样本较少，暂无法完整验证」，不编造数据。
   - 原 v2.2 的弹窗保留为「完整依据 ›」，包括需求匹配、引用笔记和反馈。
4. **交叉验证提示**：AI 回答字段 `show_cross_verify_tip` 为 true 时，在推荐列表末尾显示一条中性提示：「该话题下存在较多不同视角的分享，建议结合原文评论区综合判断」。
5. **文案中性化**：不再出现「真实用户」「建议对比参考」「无合作标识」「套路文案」等带判断的说法，也去掉黄色的合作卡片样式。
6. **微动效**：
   - 可点击元素按下时缩小到 scale(.97)。
   - 面板用 grid-rows 过渡展开，箭头旋转 180°，条形图从 0 增长。
   - 角标点击时闪一下。
   - 系统开启 `prefers-reduced-motion` 时关闭以上动效。
7. **埋点**：
   - `click_source_tag`：带 click_count、source_page、note_id、collab_status。
   - `expand_verify_panel`：带 expand_count。
   - `click_who_users`。
   - `jump_user_home`。
   - `cross_verify_tip_expose`：只在首次曝光时记录。
   - 负反馈：点踩沿用 `click_feedback`，举报记为 `report`。

## 状态矩阵（验证面板）
| 状态 | 表现 |
|---|---|
| 加载 | 3 行骨架屏，约 400ms |
| 正常 | 4 个维度 +「这 X 位是谁」+「完整依据」 |
| 样本不足（D） | 灰色说明 + 数据来源 +「完整依据」 |
| 离线 | 显示「验证数据加载失败」+「重试」 |
| 无可公开用户 | 隐藏「这 X 位是谁」入口 |
